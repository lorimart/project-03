# Project Scope Statement: 'The Mana Potion Lounge' Website

## 1. Project Purpose  
The Mana Potion Lounge is a fictional gaming-themed cafe and esports lounge. To establish a strong community presence, attract local gamers, and drive foot traffic, the business requires a clean, professional online storefront. This project will deliver a two-page website that introduces the lounge's unique amenities (console rentals, themed refreshments), outlines operational details (hours, location), and provides a way for patrons to make contact for event inquiries.

## 2. Product Description
The final product will be a responsive, two-page static website built using semantic HTML5 and styled with a single external CSS3 stylesheet. 
*  **Homepage _(index.html)_:** Features a welcoming hero banner with the business tagline ("Drink up. Buff up. Level up."), a visual grid showing 3 core features (Gaming Stations, Tabletop Area, Themed Menu), and a prominent Call to Action (CTA) button leading to the About page.
*  **About Page _(about.html)_:** Features how to business got started, operational details (hours, physical address placeholder), an interactive map asset placeholder, and a mock contact/reservation form (Name, Email, Message box).
*  **Style Sheet _(style.css)_:** This is a single CSS file used to style both pages so they match perfectly. It uses a "gamer noir" look, which is basically a dark mode theme with neon blue and neon red accents. I used simple fonts and standard flexbox and grid layout tricks to make sure everything lines up nicely on different screens.

## 3. Project Desired Results
To satisfy the requirements for Project 03, the following deliverables will be completed and housed within a single public GitHub repository:
*   `README.md`: The repository homepage outlining the project purpose, setup instructions, and links to the live site and documentation.
*   `index.html`: The fully coded homepage.
*   `about.html`: The fully coded about and contact page.
*   `style.css`: The central external stylesheet styling both pages consistently.
*   `docs/final-project-scope.md`: This comprehensive Project Scope Statement.
*   `docs/plan.md`: A project plan containing a TAME risk analysis and a Work Breakdown Structure (WBS) schedule.
*   `docs/retrospective.md`: A post-project process reflection.

## 4. Project Exclusions
To avoid scope creep and ensure timely completion before the due date, the following features are strictly excluded from this project phase:
*   Active business capabilities or online merchandise/food ordering processing.
*   A backend database for user accounts, profiles, or actual data storage.
*   Live, real-time table or gaming console booking systems (the form is a front-end mockup only).
*   Hosting or embedding external community forums or live Discord chat widgets on the site.
*   Getting caught up on specific "business" details, only focusing on assignment requirements and keep it basic.

## 5. Acceptance Criteria
The project will be considered successful and complete when it meets the following minimum expectations:
*   The repository is public on GitHub with a professional, comprehensive README.
*   Both HTML files pass structural validation and contain clear semantic markup.
*   The CSS file successfully links to both pages, ensuring a uniform visual theme without broken layouts.
*   The website is fully functional when hosted via GitHub Pages, with all internal navigation links operating correctly.
*   All three required documentation files exist within the `docs/` folder.
*   User Experience (UX) Baseline: A standard user can intuitively find critical business information (operational hours, physical location, and contact form) within a single click from any location on the site.
*   Map Asset Definition: The about.html page must feature a clearly styled, embedded frame container acting as a visual map placeholder to simulate real-world navigation utility.

## 6. Project Constraints
*   **Time:** The project must be entirely completed, tested, and submitted by the final course deadline at the end of the semester(Thursday October 1, 2026 11:59 PM).
*   **Technical:** The site must be built strictly using plain HTML and CSS without relying on external frontend frameworks or backend server languages.
*   **Scope:** The site will be limited to two pages to comply with project resource guidelines.
