# Project Retrospective: The Mana Potion Lounge Website

This post-project reflection evaluates the development process of the two-page web prototype for The Mana Potion Lounge, analyzing procedural successes, execution challenges, and personal development adjustments based on the frameworks found in Chapter 7 of *Project Management for the Unofficial Project Manager*.

## 1. What Went Well?
* **Iterative Planning Workflow:** The upfront creation of the Project Scope Statement (`final-project-scope.md`) and Work Breakdown Structure (`plan.md`) successfully prevented scope creep. By clearly mapping exclusions early, no time was wasted attempting to build complex database components or scripting engines.
* **Responsive Visual Styling:** Utilizing a centralized stylesheet (`style.css`) with unified color styling allowed for rapid theme implementation. Setting up the layout cleanly using Flexbox for global navigation, structural sections, and content positioning ensured the site seamlessly adapted across both desktop and mobile layouts.
* **Meaningful Peer Integration:** Actively applying the feedback received during the Week 07 peer reviews distinctly enhanced the product layout. The addition of structured operational details and a clearly designated dashed map footprint block resolved potential layout omissions before final deployment.

## 2. What Could Be Improved?
* **Local vs. Server Asset Simulation:** During early drafting, managing structural layouts for the map and forms created initial complexity. Moving away from over-engineered layout concepts allowed me to simplify the code into standard, native HTML5 block structures that better fit the project scope.
* **Accelerated Timeline Balancing:** Because the development phase took place over a tight window, the pace of shifting directly from text planning to active coding felt highly compressed. Building in more frequent self-reviews during coding would have made the transition smoother.

## 3. What Would I Do Differently Next Time?
* **Early Live Environment Verification:** Next time, I will configure and deploy the repository to an active server environment (like GitHub Pages) on day one rather than waiting until the end of the development phase. Testing code in a live production environment early ensures that path case-sensitivity or relative routing issues are identified and resolved immediately.
* **Proactive Visual Layout Planning:** On future web projects, I will spend more time mapping out the layout containers and CSS architecture on paper before writing the actual HTML structural tags. This would make organizing the parent-child relationships and flex arrangements faster when starting the codebase.
